# 跨平台皮革排样软件 - 竞品功能对标与保护

## Goal

打造一款可在 macOS 和 Windows 上使用的桌面软件，实现皮革/鞋面裁片的自动排样优化。第一阶段对标竞品已确认的核心功能，Windows 端同时覆盖工厂现有老旧电脑的合理兼容范围。采用**在线激活 + 离线宽限期**方案（硬件指纹绑定 + 周期性联网校验）保护知识产权，降低边际成本。

## Background

### 项目起源

已有可运行的 Python CLI Demo（`leather_nesting_demo.py`），证明了：
- DXF 文件读写链路畅通（ezdxf）
- 纯 Python 多边形几何引擎可用（碰撞检测、距离计算、点包容）
- 确定性货架排样可输出合理结果（0°/180° 旋转，~42-44% 利用率）
- DXF + PNG + JSON 三种输出格式可行

### 竞品参考

`03-测试数据/划线/` 目录包含竞品 DXF 输出（38-45.DXF，8 个鞋码尺码），是竞品划线结果的参考样本。

### 市场判断（来自已有调研）

- 中国皮革行业规上企业营收 1.13 万亿元（2022 工信部数据）
- 商用皮革排样系统（Zünd MindCUT、AutoNester-L、NestLib、GBOS ITS2）均以皮张质量、瑕疵避让、方向约束和人工复核为标准能力
- 建议先切入第一层客户：已有 DXF、每周反复排同类鞋面、能提供人工排样基线的鞋材工厂

### 已有调研文档

- `docs/research/2026-07-27-leather-nesting-market-and-algorithm.md`：市场、竞品、算法路线完整调研
- `docs/plans/2026-07-27-leather-nesting-demo.md`：Demo 的 5 阶段实现计划
- `docs/superpowers/specs/2026-07-27-leather-nesting-demo-design.md`：Demo 设计文档

## Confirmed Facts

1. **文件格式**：输入输出以 DXF（AutoCAD 通用格式）为主；业务内部统一使用毫米，但实际样本存在单位未声明或头信息与业务约定不一致，导入时必须诊断并允许人工确认
2. **核心算法**：Demo 为确定性货架填充（面积降序 + 左下优先 + 精确轮廓检查），不保证全局最优
3. **算法路线图**（已有调研结论）：订单/规则层 → NFP 几何层 → 启发式优化层 → 视觉 AI 层（独立项目）
4. **竞品数据**：已有 8 个竞品 DXF 输出文件（38-45）可分析
5. **运行环境**：macOS 和 Windows 桌面平台，核心排样功能必须离线可用
6. **IP 保护**：需要加密狗或替代方案
7. **客户环境**：工厂现场存在老旧 Windows 电脑；产品必须明确兼容边界，对不能运行的系统提供可执行的 Windows 升级或设备替换指引

## Requirements

### R1: macOS / Windows 桌面应用

- macOS 和 Windows 原生运行，提供完整的图形用户界面（非命令行）
- 联网需求：首次激活必须联网，之后每 30 天后台尝试刷新授权，断网宽限期 60-180 天
- 核心排样功能在断网期间完全可用，仅超宽限期后降级
- 安装包≤1GB，依赖自包含

### R2: DXF 输入解析

- 读取 DXF 格式的裁片轮廓数据
- 支持闭合 `LWPOLYLINE`、旧式 `POLYLINE`、`LINE`/`ARC` 组合以及可控离散化后的曲线，不得只处理一种实体类型
- 自动识别明确闭合的外轮廓和孔；开放、断裂、自交、重复或单位不明的输入进入诊断/修复流程，不得静默丢弃或擅自封闭
- 支持弧线和曲线的可控公差离散化
- 正确解析坐标单位、图层、闭合标志和弧段信息；单位缺失或冲突时要求用户确认并记录到导入报告
- 保留原始文件指纹、规范化结果、修复操作和未解决问题，使导入过程可追溯、可撤销、可重演

### R3: 排样优化引擎

- 在给定的矩形皮革区域内自动计算裁片最优摆放位置
- 支持 0°/90°/180° 旋转和镜像翻转
- 支持裁片间距（gap）和皮革边缘预留设置
- 碰撞检测：裁片之间不重叠、不超出皮革边界
- 可选角度约束（纹路/毛向限制）

### R4: 排样结果可视化与导出

- 排样结果实时可视化（画布渲染）
- 导出 DXF 格式排样图（兼容 AutoCAD）
- 导出 PNG/图片预览
- 导出排样报告（利用率、裁片清单、未放置裁片）

### R5: 知识产权保护（在线激活方案）

- **硬件指纹采集**：采集 CPU 序列号 + 主板序列号 + 硬盘序列号 + MAC 地址，生成唯一机器码
- **激活码验证**：用户输入激活码，首次激活需联网 → 服务器用 Ed25519 私钥签发授权文件
- **离线使用**：授权文件本地加密存储，每次启动校验签名 + 机器指纹匹配
- **周期性校验**：后台每 30 天尝试联网刷新授权，无需用户操作
- **宽限期降级**：超过 60 天未刷新 → 只能查看不能导出/新建排样；超过 180 天 → 拒绝运行需重新激活
- **激活码控制**：每个激活码可限制激活次数、有效期、功能权限
- **安全加固**：授权文件 AES 加密 + 时钟回滚检测 + 多检查点分散
- **可选加密狗**：为完全离线客户提供加密狗版本（溢价方案），详见 `加密狗/01-加密狗方案.md`

### R6: 竞品功能对标与 clean-room 实现

- 基于仓库中的竞品 DXF、操作材料和公开行业资料建立可追溯的功能矩阵
- 对已经确认且具有业务价值的行为做独立规格和实现；不得复制竞品商标、图标、素材、界面排布、文案、源代码或未知专有算法
- “银象公开资料”“仓库可观察行为”“行业通用设计”和“项目推导”必须分开标注，行业资料不能反推为银象已有功能
- 无法从证据确定的字段、默认值和按钮语义必须列入现场验证清单，不得用猜测填入生产规格
- 排样效果和输出兼容性以双方约定的样本、约束、基线、测量方法和容差验收，不使用“完全一样”作为不可测标准

### R7: 老旧 Windows 兼容与升级引导

- 在开发前收集目标工厂电脑的 Windows 版本、版本号、32/64 位、CPU、内存、显卡及外设驱动情况，形成现场环境清单
- 发布明确的兼容矩阵：“正式支持”、“尽力兼容”、“不支持/必须升级”，不使用含糊的“应该能运行”表述
- **正式支持**：仍处于微软支持周期内的 Windows 11 x64，以及 Windows 10 Enterprise/IoT LTSC 2019、2021 x64；发布矩阵须列出实际验证的版本号，不用“所有 Windows 11”代替测试
- **尽力兼容**：Windows 10 Home/Pro 22H2 x64；须在发布说明中明示其操作系统已结束微软免费支持，不承诺长期安全维护
- **不支持/必须升级**：Windows 7、Windows 8.1、Windows XP/Vista；不为这些系统维护专用旧版客户端
- Windows x86 32 位安装包不作为默认交付物；只有当现场盘点证明存在足够的实际需求，且通过性能和原生依赖专项验证后才纳入交付范围
- 软件启动时检测操作系统版本、架构和必要能力；不兼容时显示可理解的原因与后续操作，不得无提示崩溃
- 提供可离线保存或打印的《工厂 Windows 升级操作指南》，包含数据备份、兼容性检查、升级、驱动/外设恢复、业务验证与回退步骤
- 生产机升级必须先在一台试点机上验证，不得建议绕过 Windows 11 的 CPU、TPM 2.0 或安全启动要求

### R8: 分阶段交付与独立验收

- 项目至少拆分为 5 个有明确顺序的交付阶段；总体计划采用 7 个阶段，第 6 阶段形成双平台内部 MVP，第 7 阶段形成可销售版本
- 每个阶段必须产出可独立演示、可复测、可被拒收的成果，不得仅以“写了若干代码”作为阶段成果
- 每个阶段必须定义固定编号的测试用例，覆盖正常流程、输入校验、失败/取消、数据一致性与相关平台兼容性
- 每个阶段必须在 `implement.md` 中记录交付文件、测试命令、期望结果、人工验收清单和回退点
- 本阶段的自动测试和人工验收未全部通过时，不得宣布该阶段完成，也不得以后续阶段的成果倒推其通过

### R9: UI 工作流和功能边界

- UI 采用工作流导航，至少覆盖九个模块：项目/订单、CAD 导入诊断、裁片/尺码明细、CAD 修复与工艺、码齿规则库、材料与排样约束、排样运行控制、人工微调、结果校验与导出
- 每个功能必须在设计中定义前置条件、输入、动作、状态变化、输出、失败路径和撤销/恢复行为；只提供窗口或无逻辑按钮不算完成
- CAD 导入、轮廓修复、普通工艺剪口、尺码编码码齿和自动排样必须是不同的领域能力，不因竞品把入口放在同一菜单而混成一个模型
- 自动排样和人工微调必须共用碰撞、边界、间距、角度、镜像和数量验证器；任何可导出结果都必须先通过同一套阻断校验
- 运行中的 UI 不得无响应；停止、取消、超时、失败和恢复必须是可测试的不同状态，失败不得写入半成品项目
- 码齿库、材料规则和算法配置必须版本化；已保存项目锁定所用版本，库更新不得改变旧任务的复现结果
- UI 必须适配工厂常见的 1366×768 分辨率、100%/125%/150% 缩放、键盘操作、中文路径和老旧显卡的软件渲染回退
- 详细证据、模块合同和测试母表见 `research/ui-evidence-and-functional-model.md`

## Acceptance Criteria

- [ ] macOS 与兼容矩阵中“正式支持”的 Windows 环境上，安装后可直接启动，无需额外安装 Python 或 .NET Runtime
- [ ] 首次激活需联网验证激活码；断网后核心功能（查看、排样、导出）在宽限期内正常使用
- [ ] 超过宽限期后功能降级（只能查看，不能排样/导出）
- [ ] 加载凉鞋.dxf 后正确显示 9 个裁片轮廓
- [ ] 加载 38–45.DXF 时能识别其旧式开放 `POLYLINE`，给出可定位的诊断/修复建议，而不是显示为空或静默丢弃
- [ ] 选择皮革尺寸后执行排样，利用率不低于竞品同条件结果的 90%
- [ ] 导出 DXF 可被 AutoCAD 正确打开
- [ ] 生成的排样 DXF 与竞品 DXF 在 CAD 中可叠加对比
- [ ] 同一激活码在不同机器上激活时被拒绝或消耗次数
- [ ] 兼容矩阵中每个“正式支持”的 Windows 版本和 CPU 架构均在真实机器或对应虚拟机上完成安装、启动、导入、排样和导出冒烟测试
- [ ] 在“不支持”的 Windows 环境上，安装器或启动器给出明确的版本限制和升级指引，不无提示崩溃
- [ ] 《工厂 Windows 升级操作指南》已在一台非生产试点机上按步骤演练，升级后 DXF、外设驱动和排样软件验证通过
- [ ] `implement.md` 至少定义 5 个独立验收阶段，每个阶段都列出成果、测试用例 ID、测试命令、期望结果和阶段门
- [ ] 九个 UI 模块均在 `design.md` 中定义状态和失败路径，并在 `implement.md` 中至少归属一个阶段和一个固定编号测试用例
- [ ] 未经现场证据确认的银象字段或按钮语义保持为明确待确认项，不进入生产黄金样本

## Out of Scope (Phase 1)

- 不规则真皮皮张轮廓支持（先做矩形料）
- 瑕疵/质量分区识别与避让
- AI 视觉识别皮革缺陷
- 切割机/投影仪直接对接
- 云端计算/SaaS 模式
- Linux 支持
- 移动端

## Open Questions

### Q1: 技术栈选择 ✅ 已确定（2026-08-10 更新）

**C# .NET 10 LTS + Avalonia 12**

| 层 | 技术 |
|----|------|
| UI | Avalonia 12（XAML + MVVM + compiled bindings） |
| 业务逻辑 | C# .NET 10 LTS |
| 几何引擎 | C# 重写（移植自 Python Demo） |
| DXF I/O | `IDxfReader/IDxfWriter` 适配层；Stage 1 用真实样本选择具体库，不永久绑定已归档的 netDxf |
| 激活服务器 | ASP.NET Core 10 WebAPI |
| 测试 | xUnit + Avalonia.Headless |
| 打包 | dotnet publish --self-contained → 单目录 exe |

- Mac 开发：`dotnet run` 原生运行 Avalonia 窗口
- Windows 验证：`dotnet publish -r win-x64` 生成 Windows exe
- 端到端测试：Mac 上直接用 Avalonia.Headless 跑全量 UI 测试
- 第三方依赖在 Stage 1 记录版本、许可证、维护状态与安全风险；未经清单审核不得进入发布包

### Q2: IP 保护方案 ✅ 已确定

**在线激活 + 硬件指纹绑定**（方案 D）为默认，加密狗为离线客户溢价选项。
详见 `01-加密方案/加密狗/01-加密狗方案.md`。

### Q3: 竞品功能范围 ✅ 已分析

共识别 **12 个竞品**，分三个梯队，详见 `02-竞品数据分析/01-商业竞品调研/01-竞品.md`。

**核心结论：**
- 银象本地操作材料最适合提供工厂用户的功能线索，但缺少公开正式软件手册，不能据此猜测所有字段和按钮语义
- Zünd、Lectra/Gerber、Comelz、Teseo 等官方资料共同支持“订单→导入→工艺/约束→排样→人工复核→校验/导出”的领域流程
- Deepnest 可作为持续优化、停止保留当前最好结果等算法交互参考，但不能直接代表鞋材工艺和生产交接需求
- 国内产品常与设备、投影或视觉系统配套；本项目先以可独立使用的离线软件和标准文件交接切入，是否形成市场优势仍需试点客户验证
- 竞品研究只用于定义独立、可测的业务能力；实现必须遵守 R6 的 clean-room 边界

### Q4: 订单模型

建议最小模型包含订单号、客户、款号、材料、尺码配比、左/右数量、优先级、交期和版本；仍需用一家试点工厂的真实订单确认字段、状态流和导入方式。

### Q5: 银象 UI 语义待现场确认

- 码数 19.50、0.0–6.5 和 31–37 的关系
- 方形/半圆/尖角/半码的有序排列、锚点和方向
- 常规、使用库、自定义三种模式的互斥语义和默认值
- “停止排版”“取消排版”以及截断标签 `替换反` 的准确行为
- 设备交接文件、图层/刀具映射和通信协议

现场材料清单和调查方法见 `research/ui-evidence-and-functional-model.md` §6。

### Q6: 长期支持技术版本 ✅ 已确定

采用 .NET 10 LTS + Avalonia 12；具体 SDK 和 NuGet 补丁版本由 `global.json`、中央包管理和依赖锁定文件固定。补丁升级必须通过正式平台矩阵、真实 DXF 和发布签名回归。

## Risk Items

| Risk | Mitigation |
|------|-----------|
| 竞品有专利保护 | Phase 1 做竞品功能分析，避免直接复制受保护算法 |
| 加密狗被破解 | 多层保护（代码混淆 + 加密狗 + 关键逻辑服务端验证），但 Phase 1 仅离线 |
| 算法性能不足 | 从货架填充演进到 NFP + 启发式优化，有清晰路线图 |
| macOS 与多种 Windows 环境差异 | 核心领域层不依赖 UI/操作系统；CI 覆盖双平台，正式支持的 Windows 版本再做真实机或 VM 验收 |
| 工厂 Windows 版本老旧 | 开发前做现场设备盘点；按“正式支持/尽力兼容/必须升级”分层；提供试点升级、驱动备份和回退指南 |
