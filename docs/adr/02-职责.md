# ADR：软件职责边界与输出契约

Status: accepted（2026-08-13）

## 背景

皮革划线排样软件的定位是完成「裁片排样」，而非生成切割刀路。下游由切片软件接收排样结果并生成刀路。本 ADR 明确软件职责边界、输出契约，以及排样算法的位姿范围。

## Decision

### 1. 职责边界

本软件只负责：

1. 读入裁片轮廓（DXF 等）；
2. 排样（nesting）—— 在皮革/材料区域内计算裁片位姿，追求材料利用率；
3. 输出排样结果文件，交给下游切片软件。

本软件**不负责**：

- 切割刀路（toolpath / G-code）生成 —— 由下游切片软件完成；
- 切片软件的厂商兼容适配 —— 通过标准格式（DXF / JSON）解耦，不针对单一厂家定制。

### 2. 输出契约

- 输出格式：**DXF 与 JSON 两种都要**。
- 分阶段实施：**先做 DXF 输出**；**JSON 输出暂缓**。
- JSON 暂缓理由：JSON 是通用协议，多数切片软件都能兼容，无需针对特定厂家逐一适配，因此不阻塞 DXF 先行。JSON 的设计原则与待办字段见 [`json输出契约待办.md`](../todo/01-json输出契约待办.md)。

### 3. 排样算法位姿范围（升级）

- 位姿范围为 **任意角度（自由旋转）**，不限于 0° / 90° 等固定倍数。
- 含义：每个裁片允许以任意旋转角放置以追求材料利用率；具体候选角度集合由旋转步长（配置）决定。
- 影响：放置候选生成需支持任意旋转角；Geometry 层已基于 Clipper2 具备旋转与布尔运算能力，且 `NestRequest.AllowedRotationsDegrees`、`PlacementCandidateGenerator.Candidates(rotationDegrees)` 已按任意角度设计。毛向 / 纹路等工艺约束可能限制实际允许的角度集合——这是在任意角度基础上**叠加约束**，而非退化为固定角度。

> 修订记录：2026-08-15 将位姿范围由「0° / 90°」更正为「任意角度」，与代码层 `AllowedRotationsDegrees`（任意角度列表）对齐。

## Evidence and limits

- 现有 Demo（`leather_nesting_demo.py`）为确定性货架填充，仅 0°/180°，README 明示「不保证全局最优」。
- DXF 读取已由自研 `AsciiDxfReader` 承担（见 [`01-dxf-adapter.md`](./01-dxf-adapter.md)）；DXF 写出原计划属 Stage 5 边界，本 ADR 将其提前纳入输出契约。
- 任意角度旋转是排样核心能力；毛向 / 纹路、镜像、part-in-part 属约束扩展，建立在同一任意角度基础上，不在本 ADR 范围内。

## Consequences

- 职责收敛后，「排样利用率」成为唯一核心质量指标；刀路、切片兼容从本软件剥离。
- 排样算法以任意旋转角为候选姿态，碰撞/间隙验证需对旋转后轮廓正确（SAT / Clipper2 布尔）。
- 输出层以 DXF 先行；JSON 字段冻结后再实现，避免与切片软件实际解析需求脱节。
