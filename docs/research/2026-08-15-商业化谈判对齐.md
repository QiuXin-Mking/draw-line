# 排版软件商业化谈判对齐

> 用于与老板商谈排样软件商业化的对齐点、风险分工与变现路径。本文档是谈判准备，不是最终协议；数据待补充后应一并落在这里，作为下次谈话的基线。

- 与老板已完成初步沟通，确定里程碑：**约 2 个月后交付销售版 v1.0**（对应里程碑 M2：产品化完成、验收、版本冻结）。

- 风险：先交付成果、后谈商务，将落入"沉没成本"劣势——v1.0 做完后老板已有产品，谈判筹码被消耗。

**缓解动作（在 2 个月开发期内并行推进）：**

## 一、背景与定位

- 软件：皮革划线排样软件（.NET / Avalonia），只做排样，不生成切割刀路。
- 老板画像：**完全外行**，无法开发；但作为**供应商，正在卖同款软件**（排样类软件）。
- 结论：这款软件不仅是内部省钱工具，**更是老板可对外销售的产品来源**。开发者是老板软件生意的唯一技术供应方——这是本次谈判的资本。

**谈判定调：** 谈的不是"软件好不好"，而是三件事——价值怎么量化、风险怎么分、投入怎么变现。

## 二、核心立场

**"收益是老板的，风险也应该是他的"，操作化为：**

> **谁决策，谁承担。** 部署、依赖、投产都是老板的决策，生产/商业风险归老板；开发者只承担"把批准范围内活干好"的构建质量风险。

- 老板拿收益大头 → 出投入（钱/时间/资源）、担商业风险。
- 开发者控质量、担构建风险 → 对应拿分成/岗位化回报。
- **分工，不是甩锅。** 开发者的筹码正是"项目是他的"，不能全甩给老板。

**最大谈判筹码：停止免费投入。** 谈成之前，不再用自己的时间无偿加码。

## 三、对齐点清单（收益 / 投入 / 风险 / 商业）

### 1. 价值共识（收益·前提）
老板必须亲口确认：在厂内排样能省钱 / 提速 / 少浪费；并能对外卖。确认方式是**数字**，不是感觉。

### 2. 收益基线（收益·最硬一环）
至少三个数（估的也行）：
- 远程排样系统现在**一年花多少钱**（最硬的锚点）。
- 平均每张皮**浪费率**多少——材料成本是金矿，通常比系统费大一个数量级。
- 一天排多少张、每单多久（提速 → 人力/交期价值）。

> 没有基线，收益无法验证，分成就没有依据。收益必须可度量。

### 3. 先弄清现状（收益/商业·新信息引发）
- 老板现在卖的同款软件，是**转售第三方的远程系统，还是自有**？
- 本软件是**替代**它，还是**补充**它？
- 替代 → 价值主张是"更高毛利、自有产品、不养第三方"；若老板还在第三方分成上赚钱，要把"替代"包装成"升级"，避免被理解成砸饭碗。

### 4. 投入安排（投入）
- 已投入的**自己的时间**要摆上桌（变现的弹药）。
- 以后开发算**上班时间**还是业余？业余 = 老板免费吃研发。
- 测试耗材、试排皮料、软硬件预算谁出。

### 5. 里程碑与验收（投入/商业）
POC（并排对比：同张皮 本软件 vs 远程系统）→ 试点（低风险订单）→ 正式投产/销售版 → 试点客户。每阶段有明确通过标准和老板签字，逐步放量。

老板中途说不做、开发者离职、远程系统改版——项目怎么办。提前说清，既保护自己，也让老板意识到不能只靠一个人扛。

## 四、风险分工表

| 风险 | 归属 | 落地机制 |
|---|---|---|
| 开发做不出来 / 质量不达标 | 开发者（构建质量） | 仅限"批准投入的范围内" |
| 上线后生产事故、排样错误致损 | 老板（部署决策者） | 投产前老板**书面/口头批准** + 试点期 + 回退路径 |
| 依赖远程系统格式，对方改版/停止 | 老板（业务连续性） | **保留远程系统合同**当保险/回退，别一上来就退掉 |
| 投产依赖单点（开发者一人） | 老板 | 文档化、交接机制、离职/休假连续性方案 |
| 被廉价拿走（外行易"这有什么难的"） | 开发者 | 谈定前不交代码；先立 IP 归属 |
| 人质/挤压（靠开发者→榨完冷落） | 开发者 | 分成/岗位化落成文字，别只靠口头 |
| 外行决策（定不了价、验不了质量、乱承诺客户） | 老板 | 写入分工：开发者=产品交付；老板=销售/售后/客户/合规 |
| 时间沉没（无偿投入的工时） | 开发者 | 现在止损：谈成前不再加码 |

## 五、IP 归属分水岭（谈判前先查合同）

**第一件事：翻劳动合同的 IP / 职务成果归属条款。**

- **场景 A（职务开发，IP 归公司）**：开发者牌变为"唯一能维护/继续开发的人" + 谈补偿；不抢 IP，别在这上面耗。
- **场景 B（业余时间、自有 IP）**：开发者是产品权利方，谈**合作 / 授权 / 分成**，不是打白工。这是最大的杠杆，也是最大的坑。

**不管哪种：谈定之前，不交代码、不做全量演示。** 对不会开发的老板，"拿到代码"= 拿到产品。演示到"有价值"即可，核心留到有回报承诺之后。

## 六、变现方案（推荐"产品分成"）

把分成锚在**销售额/回款**上，而不是只有工资：

- **产品分成**：每卖出一套/一年授权，按销售额 10~20%（区间可谈）。前提：约定**以回款为口径**、老板确实有销售能力。
- **两条腿走路**：内部使用 + 对外销售。内部这条先落地（好验证、先变现），对外是增量。
- **备选**：一次性买断（按合理估值，不接受低价）+ 年度维护升级费；或授权费模式。
- **岗位化**：技术合伙人 / 产品负责人，责任与薪酬一起变。

> 最符合"收益是老板的、风险也该是他的"的机制就是分成：老板拿大头、担销售/市场风险；开发者按真实回款拿钱，卖不动也拿不到——风险收益都是真数字，公平。

## 七、今天的目标（三档）

- **及格**：老板意识到"这软件能变成他要卖的产品，不只是内部用"；约好下一场谈方案。
- **良好**：+ 承认开发者是产品**唯一技术负责人**；原则上认可"卖出去有钱分"。
- **优秀**：+ 授权出一页纸《产品化 + 分成》提案；明确今天**不交代码**。

**今天不要做（死线）：** 不交代码；不全量演示；不接受低价口头买断；在查清劳动合同 IP 条款前不做任何 IP 口头承诺；不承诺免费维护。

## 八、对外行老板的打法

外行老板听不懂技术、估不了价，开发者优势是**信息差**。打法：**带结构去谈**——把方案、数字、分工、里程碑全列好，让他只有"点头/摇头"一件事可做。递上的是"已经替他想好了"的提案，降低他做决定的门槛。

## 九、四阶段合作协议框架（收入 / 产出表）

**总原则：** 开发者不承担长期维护（维护归属公司员工）；收入按阶段切换——前期拿开发投入回报，中期拿过渡支持费，售卖期起拿销售分成。分成一律以**实际回款**为口径。

### 阶段总览

| 阶段 | 开发者角色 | 公司角色 | 开发者收入 | 公司投入 | 阶段产出 |
|---|---|---|---|---|---|
| 1 前期投入期 | 开发 / 产品化 / 交接文档 | 出钱、出资源、验收 | 里程碑开发费 | 开发费 + 物料 + 皮料 | 销售版 v1.0 + 全套文档 |
| 2 维护期（过渡） | 培训公司员工 + 限时兜底 | 员工接手维护 | 过渡支持费 | 支持费 + 员工培训工时 | 独立维护能力（考核通过） |
| 3 售卖期 | 售前支持 / 版本迭代 | 销售、商务、售后 | 销售额分成 X% | 渠道与销售成本 | 首单 → 稳定订单 |
| 4 稳定出货期 | 重大升级 / 架构级兜底 | 全链负责 | 阶梯或固定分成 | 运营成本 | 稳定出货 + 累计收入 |

### 阶段 1 · 前期投入期（完成销售版 v1.0）

**目标：** 把现有软件变成可验收、可交付、可销售的版本。

| 投入（开发者） | 投入（公司） | 产出（交付物） | 收入（开发者） | 验收节点 |
|---|---|---|---|---|
| 已投入工时（折算进谈判）、剩余开发、产品化（打包/安装/手册）、交接文档 | 开发费、测试皮料与耗材、软硬件、试排环境 | 销售版 v1.0；验收报告；用户手册；交接/知识库文档 | 里程碑开发费（建议分两笔：交付 v1.0 付首期、验收通过付尾款） | 并排对比通过；验收签字；版本冻结 |

**谈判要点：**
- 若公司不愿付现金开发费，等价交换：提高后续分成比例，或延长分成年限，作为已投入工时的折算。
- 里程碑款是"不能一直独立投入"的落地——前期必须有现金回报，否则只靠画饼。

### 阶段 2 · 维护期（过渡，建议 3~6 个月）

**目标：** 把维护完整交给公司员工，消除单点依赖。

| 投入（开发者） | 投入（公司） | 产出（交付物） | 收入（开发者） | 验收节点 |
|---|---|---|---|---|
| 员工培训（维护/排样规则/常见问题）、限时技术兜底（如 3~6 个月）、疑难分诊 | 指派维护员工、培训工时、测试环境、支持费 | 独立维护能力；培训记录；问题知识库 | 过渡支持费（按月或打包价） | 员工考核通过 = 兜底期结束 |

**谈判要点：**
- **兜底条款：** 若考核不通过，员工仍无法独立维护，维护责任仍在公司；开发者按日/按次付费支持，不再免费兜底。
- 兜底期结束 = 开发者从日常维护退出，转岗为"重大升级 + 顾问"。

### 阶段 3 · 售卖期（对外销售，拿分成）

**目标：** 公司渠道把产品卖出去，开发者按回款分成。

| 投入（开发者） | 投入（公司） | 产出 | 收入（开发者） | 节点 |
|---|---|---|---|---|
| 售前技术讲解/演示、定制需求评估、配合迭代 | 销售渠道、商务、合同、客户管理、售后 | 销售额、售出套数、回款明细 | 销售额 X% 分成（建议 10~20%），以**回款**为口径 | 首单签订；季度对账 |

**谈判要点：**
- **口径：** 分成基数 = 实际回款（税前）。是否扣渠道佣金/销售提成必须写明；建议"面向最终客户的回款全口径，已明确的渠道佣金除外"。
- **对账权（关键）：** 开发者有权每季度查看财务回款明细；虚报回款的违约条款（自动上浮比例 + 违约金）写进去，防外行老板压数。
- **首单激励：** 可约定首单落袋后一次性奖励，或当年比例上浮 1~2%，绑定短期动力。

### 阶段 4 · 稳定出货期（出货稳定，收益递减或封顶）

**目标：** 产品成熟、出货稳定，开发者逐步淡出。

| 投入（开发者） | 投入（公司） | 产出 | 收入（开发者） | 节点 |
|---|---|---|---|---|
| 重大 bug / 架构级问题 / 大版本升级 | 员工维护、销售、产能、运营 | 稳定出货量、累计回款 | 阶梯式递减分成，或固定比例 + 年限/累计封顶 | 封顶或年限到达；退出结算 |

**谈判要点（收益结构二选一）：**
- **阶梯递减：** 如首年 15% → 次年 10% → 第 3 年起 5%，或前 50 套高、其后递减。维护已转移给公司，开发者持续成本低，递减是公平的。
- **固定 + 封顶：** 固定 10% 持续 3 年，或累计分成达某上限即终止。
- 封顶/年限条款既保护公司长期现金流，也给你明确预期，避免"永远挂账"。

### 经济机制核心条款（贯穿四阶段）

| 条款 | 建议内容 |
|---|---|
| 分成口径 | 实际回款（税前）；扣什么、不扣什么列清单 |
| 结算周期 | 按季度对账、回款后 30 天内支付 |
| 对账权 | 开发者可查财务回款明细；虚报 = 比例上浮 + 违约金 |
| 分成期限/封顶 | 阶梯递减或年限/累计封顶（阶段 4 定） |
| 维护归属 | 阶段 2 考核通过后，日常维护归公司员工；开发者只担重大升级 |
| IP 归属 | 见第五节；代码归属与分成机制必须同一份协议写清 |
| 竞业与保密 | 双向：开发者不另做同款竞品（约定年限）；公司不将代码转授第三方 |
| 退出与终止 | 终止后存量客户回款仍按比例分成至封顶/年限；新版本不再参与 |
| 争议处理 | 本地仲裁/法院 + 以回款单据为准 |

> ⚠️ 本文是谈判框架，不是法律文本。正式签之前建议请律师把上述条款转成合规协议（尤其 IP 归属、分成结算、竞业限制在中国法律下的效力）。

## 十一、一页纸《产品化 + 分成提案》骨架（待填充数字）

1. **产品定位**：内部用 + 对外卖；卖成"把鞋面 DXF、订单数量、皮革工艺规则变成可审核、可导出、可对比耗料的排样单"。
2. **收益基线表**：远程系统费 / 材料浪费 / 提速 —— 留空填数。
3. **里程碑**：内部并排验证 → 销售版 → 试点客户。
4. **风险分工表**：见第四节。
5. **分成方案**：按回款 X%（10~20%），内部省下费用另算。
6. **给老板看的"今天只需点头三件事"**：价值方向 / 出钱出资源 / 授权出提案。
