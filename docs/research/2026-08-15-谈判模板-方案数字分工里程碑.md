# 排版软件合作提案 · 谈判模板（方案 / 数字 / 分工 / 里程碑）

> **用法：** 去谈之前把每处 `____` 填上数字，按顺序把四个板块走一遍。老板是外行，你递上的是一份"已经替他想好了"的方案，他只需要点头/摇头。
> 括号里是建议区间，不是定死值。

---

## 一、一句话定位（30 秒讲清"这是啥"）

本软件 = **把鞋面 DXF、订单数量和皮革工艺规则，变成可审核、可导出、可对比耗料的排样单**（排样软件，不生成切割刀路）。

两条腿：
- **内部用**：本地排样 → 省远程系统费、省皮料浪费、提速。
- **对外卖**：公司的销售渠道 + 这份软件 = **自有产品**，更高毛利，不养第三方。

---

## 二、方案（Plan）——四阶段怎么走

| 阶段 | 干什么 | 谁掏钱 | 产出物 |
|---|---|---|---|
| ① 前期投入期 | 开发 + 产品化（打包/手册/交接文档） | 公司出开发费、物料、皮料 | 销售版 v1.0 |
| ② 维护期（过渡） | 培训公司员工接手维护 + 限时兜底 | 公司出支持费、培训工时 | 独立维护能力 |
| ③ 售卖期 | 对外销售，按回款分成 | 公司出销售、商务、售后 | 首单 → 稳定订单 |
| ④ 稳定出货期 | 开发者只担重大升级 | 公司全链负责 | 稳定出货 + 累计收入 |

**给老板的一句话收益：** 前期出一笔开发费，之后既是省钱的内部工具，又是能卖钱的产品；维护由你的员工管，不用养着我一个人。

## 四、分工（谁做什么 / 谁担什么）

### 四阶段分工

| 阶段 | 开发者 | 公司 / 员工 | 老板决策 |
|---|---|---|---|
| ① | 开发、产品化、交接文档 | 出钱、出物料、验收 | 批准开发费、批预算 |
| ② | 培训员工、限时兜底 | 员工接手日常维护 | 定维护员工、批培训 |
| ③ | 售前技术、配合迭代 | 销售、商务、售后 | 定售价、签合同、批回款 |
| ④ | 重大升级、架构兜底 | 员工维护、销售、运营 | 定方向、批大版本 |

### 风险分工（谁决策谁承担）

| 风险 | 归属 | 一句话 |
|---|---|---|
| 开发质量 / 交付达标 | 开发者 | 我在批准范围内把活干好 |
| 上线生产事故 / 排样错误致损 | 老板 | 投产是你批准的决定，回退路径随时在 |
| 依赖远程系统格式变更 | 老板 | 保留远程系统合同当保险 |
| 单点依赖（只有我会） | 老板 | 员工培训 + 交接文档解决 |
| 客户售后 / 合规 | 老板 | 员工维护团队负责 |

**给老板的一句话：** 收益的大头是你的，所以生产、销售、售后的风险也归你决策；我只对我交付的产品质量负责。

## 八、老板可能的话术 → 应对

| 老板说 | 应对 |
|---|---|
| "这有什么难的？" | 亮已投入工时清单 + 第三方系统售价，算出我搭的人工 |
| "先做出来再说" | 好，签框架 + 里程碑付款；或先把内部并排对比做出来，再谈对外 |
| "员工能维护，你不用管了" | 可以，那就交接 + 兜底期；之后付费支持，不白干 |
| "分成太高了" | 对比第三方系统的价格/分成，让他看到省下的钱里我拿的是小头 |
| "卖不出去怎么办" | 那分成拿不到，我认——但内部省下的钱是硬数字，先走内部这条腿 |
| "这是我工作职责内的事" | 那就转成工作职责：开发计入工时、公司出资源、IP 归公司，按正常薪酬走 |
