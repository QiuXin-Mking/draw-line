## 二、技术路线分析

### 2.1 核心算法

NestLib 是一个 **全自动 True Shape Nesting（真形排样）** 算法库，被行业公认为最快、最强大的自动排样库之一。其算法路线如下：

| 维度 | 描述 |
|------|------|
| **核心几何计算** | No-Fit Polygon（NFP，无干涉多边形）-- 使用 Minkowski Sum 计算两个任意多边形之间的所有不重叠放置位置 |
| **优化策略** | **遗传算法（Genetic Algorithm）** + 启发式策略 -- GA 用于优化零件排列顺序和旋转角度，结合面积排序（大件优先）等启发式规则 |
| **NFP 缓存机制** | 预计算并缓存 NFP 结果以避免重复计算，这是工业级排样系统实现高速运行的关键技术手段 |
| **多核并行** | 支持双核、四核并行计算，加速排样过程 |
| **零件嵌套** | 支持 Part-in-Part Nesting（零件套裁）-- 小零件可放置在大零件的内部孔洞中 |

#### 算法性能数据

根据韩国一项对比研究，NestLib 在标准测试集上的表现：

| 测试案例 | NestLib 废料率 | 对比算法（VLT） | NestLib 耗时 | 对比算法耗时 |
|----------|--------------|----------------|------------|------------|
| Albano 基准 | ~21.11% | 15.05% | ~2 秒 | 113 秒 |
| 布料排样基准 | ~18-21% | -- | 数秒 | -- |

关键洞察：NestLib 更注重 **速度与效率的平衡**，适合工业实时应用场景。虽然纯学术算法可能达到更低的废料率，但通常需要 50-100 倍的运算时间。

### 2.2 皮革排样模块的特殊处理

NestLib Leather 是 NestLib 的 **可选高级模块** 之一，专为真皮排样设计。其核心特点：

1. **质量区域（Quality Zones）处理**：真皮皮革存在天然的质量不均一性（不同区域的纹理、密度、伤痕不同），Leather 模块能够识别并分区处理这些不同质量等级的区域，确保高质量零件匹配高质量区域。

2. **缺陷避让**：天然皮革的孔洞、伤痕等缺陷区域可被标记并自动避让。

3. **不规则轮廓**：皮革张幅本身轮廓极不规则，零件形状也高度异形，NestLib 的 True Shape 算法能够处理这种复杂性。

4. **纹理方向约束（Grain Direction）**：支持对皮革纹理方向的约束，某些零件（如汽车座椅面套）对纹理方向有严格要求。

5. **不规则边界**：不像金属板材是规则的矩形，皮革张幅是不规则形状，这也是 Leather 模块与基础模块的核心差异之一。

### 2.3 实现语言与交付形式

| 维度 | 详情 |
|------|------|
| **核心语言** | C/C++（提供 C 语言 API 接口） |
| **交付形式** | 静态库（.lib）、DLL（动态链接库）、COM DLL |
| **语言绑定** | Java 封装、.NET Framework（C#）封装 |
| **编译器（Windows）** | Visual Studio 2012（标准交付），32 位 DLL 可与其他编译器集成 |
| **无源码交付** | 以二进制 SDK 形式提供，不开放源码 |

## 三、软件框架分析

### 3.1 SDK 架构

NestLib 的架构可抽象为三层：

```
┌─────────────────────────────────────────┐
│        宿主 CAD/CAM 应用程序              │
│  （如 NESTINGWorks for SOLIDWORKS）      │
├─────────────────────────────────────────┤
│        NestLib C API 接口层              │
│  输入：零件/张幅几何 + 排样参数           │
│  输出：每个零件的变换矩阵（位置+旋转）      │
├─────────────────────────────────────────┤
│        核心排样引擎                       │
│  ├── 基础模块（True Shape Nesting）       │
│  ├── Leather 模块（质量区域处理）          │
│  ├── Shear 模块                         │
│  ├── Common Cut 模块                    │
│  ├── Tube 模块                          │
│  ├── Remnant 模块                       │
│  └── PCB / IFM / Snap 等模块            │
└─────────────────────────────────────────┘
```

### 3.2 API 工作流程

1. **输入端**：宿主程序通过 C API 传入：
   - 排样参数（分辨率、刀具直径、零件间隙等）
   - 零件列表（数量、允许旋转角度、优先级等）
   - 张幅列表（张幅尺寸、排样方向、排样起始角等）
   - 几何数据（每个零件和张幅的轮廓顶点数据）
   
2. **处理端**：NestLib 内部执行排样计算

3. **输出端**：返回每个已排样零件实例的 **变换矩阵（Transformation Matrix）**，指示该零件的旋转角度和平移位置

### 3.3 文件格式处理

NestLib **不原生支持任何文件格式**。宿主应用程序需要自行读取 DXF/DWG 等 CAD 文件，解析几何数据后通过 API 传递。评估版附带一个 DXF 读取器的参考实现。

### 3.4 支持的平台

| 平台 | 状态 |
|------|------|
| **Windows 32-bit** | 正式支持（静态库 + DLL） |
| **Windows 64-bit** | 正式支持 |
| **Linux** | 正式支持 |
| **Sun Solaris** | 正式支持 |
| **macOS** | 按需提供（On Demand） |

### 3.5 集成周期

根据官方的说法，在 Windows 平台上的基础集成 **通常不到 5 个工作日**。HCL 也可派遣工程师到客户现场提供集成和培训服务。

### 3.6 生态：NESTINGWorks

NestLib 是纯 SDK，终端用户无法直接使用。HCL 最重要的终端产品是 **NESTINGWorks**--一个集成在 SOLIDWORKS 内部的 3D 自动排样插件：

- **首次发布**：2016 年 1 月，SOLIDWORKS World 大会
- **宿主平台**：SOLIDWORKS（2016-2026 版本）
- **工作方式**：用户在 SOLIDWORKS 中直接进行排样操作，所有嵌套结果输出为 SOLIDWORKS 装配体，与原始设计保持关联（设计变更自动反映到排样结果）
- **材料支持**：钣金、板材、塑料、复合材料、木材、**织物/纺织品、皮革**
- **下游衔接**：排样结果可直接输入 CAMWorks 生成 CNC 代码
- **功能继承**：NESTINGWorks 作为 NestLib 的上层应用，继承了所有模块的能力，包括 Leather 模块

## 四、收费模式分析

### 4.1 授权模式

NestLib 采用 **OEM / ISV 授权模式**而非终端用户模式：

- **价格不公开**：官网和公开材料中均未列出具体价格
- **按询价（Quote-based）**：需联系 `tech.sales@geometricglobal.com` 获取报价
- **评估版本可用**：可从官网下载评估版进行试用

### 4.2 价格推测

基于行业经验和对 NestLib 定位的分析：

| 推测维度 | 分析 |
|----------|------|
| **基础模块** | 估计 **$5,000 - $15,000** / 授权（一次性买断） |
| **Leather 高级模块** | 估计在基础模块上额外增加 **$3,000 - $8,000** |
| **整体价格区间** | $5,000 - $25,000（取决于所选模块数量） |
| **授权类型** | 主要是一次性买断（Perpetual License），可能伴随年度维护费 |
| **OEM 集成授权** | 如果集成到自有产品再分发，可能采用 Royalty 模式（按最终用户数量收费） |

**不确定性声明**：以上价格均为行业推测，NestLib 的实际定价策略未知。考虑到 HCL 是一家大型 IT 服务公司（年收入 130 亿美元+），NestLib 并非其核心收入来源，定价策略可能更灵活，甚至可能与 HCL 的其他工程服务捆绑销售。

### 4.3 HCL 的定价逻辑推测

HCL 可能采取的几种定价策略：

1. **按年订阅（SaaS）**：对于需要持续更新和技术支持的客户
2. **一次性买断 + 年度维护费**（18-20% / 年）：传统 OEM 模式
3. **Royalty 分成**：集成商销售终端产品时按 license 数分成
4. **捆绑销售**：与 CAMWorks、DFMPro 等 HCL 其他产品捆绑

## 六、UI 使用方式分析

### 6.1 根本定位：没有 UI 的算法库

NestLib 的核心定位是 **算法库（Library）**，本身 **不提供任何用户界面**。这一点是其商业模式的关键特征：

- **目标客户是软件开发者**，而非终端工厂操作人员
- 宿主程序负责 UI、文件导入导出、报表生成等
- NestLib 只负责"给定一批零件和张幅，告诉我最优排列方式"

### 6.2 终端用户的使用路径

终端用户通过以下方式间接使用 NestLib 的能力：

```
路径一：NESTINGWorks（自有终端产品）
  用户 → SOLIDWORKS → NESTINGWorks 插件 → NestLib 引擎

路径二：第三方 CAD/CAM 软件（OEM 集成）
  用户 → [某 CAD/CAM 软件] → [内置 NestLib] → NestLib 引擎

路径三：企业定制开发
  用户 → [企业自研排样系统] → NestLib SDK
```

### 6.3 HCL 的终端产品矩阵

| 产品 | 类型 | 说明 |
|------|------|------|
| **NESTINGWorks** | SOLIDWORKS 插件 | 3D 真形自动排样，支持钣金/皮革/织物等 |
| **CAMWorks** | SOLIDWORKS 集成 CAM | 数控编程，与 NESTINGWorks 紧密集成 |
| **DFMPro** | 设计可制造性分析 | 不直接关联 NestLib，但同属 HCL 制造产品线 |
| **NestLib SDK** | 算法库 | 核心产品，供 OEM 集成 |

### 6.4 与竞品的 UI 差异

| 维度 | NestLib | SigmaNest | Jetcam | Lantek |
|------|---------|-----------|--------|--------|
| **产品形态** | SDK（无 UI） | 独立应用程序 | 独立应用程序 | 独立应用程序 |
| **终端用户** | 通过宿主程序间接使用 | 直接操作软件 UI | 直接操作软件 UI | 直接操作软件 UI |

## 七、竞品对比总结

### 7.1 NestLib Leather 的优势

1. **经验丰富**：20+ 年的排样算法积累，125+ OEM 客户验证
2. **性能极快**：数秒内完成复杂排样任务，适合实时交互场景
3. **模块化设计**：Leather 模块独立可选，不需要的功能不付费
4. **多平台支持**：Windows / Linux / Solaris / macOS
5. **灵活的集成方式**：静态库、DLL、COM、Java、.NET 多形态交付
6. **大公司背书**：HCL Technologies（年收入 $130B+）的稳定性保障
7. **皮革专有模块**：质量区域分级的真皮排样能力在业界具有独特性

### 7.2 NestLib Leather 的劣势

1. **无独立 UI**：终端用户不能直接使用，必须依赖宿主程序
2. **无原生文件格式支持**：集成方需自行实现 CAD 文件解析
3. **价格不透明**：无法快速评估成本，可能超出小客户的预算
4. **中国市场存在感弱**：中文资料、本地支持、客户案例均匮乏
5. **算法可能不是最前沿**：2017 年后的技术迭代信息较少，可能被学术界的深度学习方法超越
6. **文档未公开**：API 文档仅向授权客户提供，公开信息极少
7. **Web 化不足**：似乎没有提供云 API 或 Web 端集成方案
8. **依赖 HCL 的战略优先级**：NestLib 在 HCL 众多业务中的战略地位可能不高

## 八、关键洞察与建议

### 8.1 对于排样软件创业者的启示

1. **SDK 模式有市场空间**：NestLib 证明存在大量需要嵌入排样能力的 CAD/CAM 厂商，SDK 模式虽然无法直接触达终端用户，但可以获取 125+ OEM 客户。这是值得考虑的商业模式之一。

2. **皮革排样有专门需求**：质量区域分级、缺陷避让、纹理约束等功能让 Leather 模块具有真正的差异化价值。如果要做竞品，这些能力需要深度实现。

3. **速度 vs 利用率的权衡**：NestLib 选择了速度优先的策略（2 秒 vs 113 秒），这决定了它的应用场景是交互式操作而非离线批量优化。新产品需要明确自己的定位。

4. **NestLib 在皮革领域的公开信息很少**：专门的 Leather 模块页面无法访问，技术细节基本未公开，说明 HCL 对此模块的市场推广并不积极，这可能意味着该模块的市场规模较小。

### 8.2 值得进一步研究的竞品

- **AutoNester-L**（scapos AG，德国）：专门的皮革排样软件，采用模拟退火 + 贪心策略 + 分支定界
- **SigmaNest**：综合排样软件，可能有一定皮革能力
- **Lantek**：车间级排样套料软件
